# jscan.php — сканер Joomla 5/6

Один PHP-файл для очистки Joomla 5 и 6 на хостинге. Он удаляет только очевидные бэкдоры. Ядро сайта, шаблоны и `.htaccess` он не трогает вслепую — спорное записывает в отчёт.

> Важно: эта страница является инструкцией в Markdown. На хостинг заливайте файл `jscan.php`, а не этот README. После работы обязательно удалите сканер с сервера.

## Что подготовить

- Файл `jscan.php` рядом с этой инструкцией.
- Доступ к файловому менеджеру / FTP на хостинге.
- Секретный ключ для сканера. Это не пароль админки Joomla, а отдельный ключ, например: `scan-7kR9pQ`.

## Пошагово

### 1) Смените ключ в файле

Откройте `jscan.php` в блокноте или редакторе. Найдите строку:

```php
const JSCAN_KEY = 'change-this-key';
```

Замените её на свой ключ:

```php
const JSCAN_KEY = 'scan-7kR9pQ';
```

Ключ в файле и в адресной строке браузера должны быть одинаковыми.

### 2) Залейте файл на сайт

Положите `jscan.php` в корень Joomla, туда же, где находятся `configuration.php` и `index.php`.

Пример пути на хостинге:

```bash
/home/c/cr00000/Site/public_html/jscan.php
```

Если вы чистите второй сайт, используйте второй `public_html`.

### 3) Откройте сканер в браузере

Подставьте свой ключ:

```text
https://yoursite.ru/jscan.php?key=scan-7kR9pQ
```

Если ключ неверный или отсутствует — появится `Forbidden`. Проверьте, что:

- ключ в файле совпадает с тем, что после `?key=`;
- файл загружен в корень сайта;
- файл не лежит в подпапке.

### 4) Нажмите «Полный цикл»

Страница будет проходить шаги автоматически. Не закрывайте вкладку, пока не появится отчёт.

| Шаг | Что происходит |
| --- | --- |
| 1 | Проверяет процессы и loadavg, уничтожает только вредоносные процессы вроде `cli/cf`. PHP и Apache не трогает. |
| 2 | Рекурсивно сканирует файлы чанками, чтобы не упереться в таймаут хостинга. |
| 3 | Карантин и удаление очевидных бэкдоров, установка прав `0755/0644`, проверка `.user.ini` без `auto_prepend_file`. |
| 4 | Формирует отчёт HTML + JSON. |

На shared-хостинге шаг 2 может идти несколько минут — это нормально.

### 5) Сохраните рапорт

Нажмите «Скачать JSON». Файл также записывается на сервер:

- `tmp/jscan-report.json` — для локального ИИ;
- `tmp/jscan-report.html` — для чтения глазами.

Если в JSON есть блок `needs_ai_fix`, откройте локальный чат с копией сайта и этим JSON. Править нужно только перечисленные пути.

### 6) Удалите сканер с хостинга

Нажмите кнопку «Удалить jscan.php» в конце отчёта или удалите файл вручную через FTP. Не оставляйте сканер на сайте.

## Что сканер удаляет сам

Только при высокой уверенности и после копии в `tmp/jscan-quarantine/`:

- аплоадеры `up_1234.pht` / `.shtml` и файлы с текстом `UPLOADER_OK` или `Gagal rename`;
- файлы с именем ровно `cf` или `rt` в папках `cli/` и `layouts/`;
- PHP/PHT/SHTML в `images/`, `tmp/`, `cache/` (не ядро Joomla);
- чужой `auto_prepend_file` в `.user.ini`.

Если копию в карантин записать не удалось — файл не удаляется, а только попадает в отчёт.

## Что сканер не трогает

- корневой `.htaccess`;
- `configuration.php`;
- `index.php` ядра Joomla;
- шаблоны и компоненты с подозрительной вставкой.

Эти файлы должен править человек или локальный ИИ по списку `needs_ai_fix`.

## Если процессы не убились

На Timeweb часто бывает `Permission denied` (errno 13). Это нормально: PHP не имеет права отправлять `kill`. В отчёте будет готовый текст тикета — скопируйте его в поддержку хостинга вместе со списком PID.

Cron в панели Timeweb PHP не видит. Проверьте задания вручную в панели хостинга.

## Не делайте так

- не заливайте сканер, не сменив ключ;
- не оставляйте `jscan.php` после работы;
- не выкладывайте ссылку с ключом в открытый чат;
- не загружайте на сайт эту HTML-инструкцию — она не нужна серверу.

## Короткий чеклист

1. Ключ в строке 10 `jscan.php` заменён.
2. Файл лежит рядом с `configuration.php`.
3. В браузере открыт URL вида `/jscan.php?key=ВАШ_КЛЮЧ`.
4. Нажат «Полный цикл» и дожданы результаты.
5. JSON сохранён.
6. `jscan.php` удалён с сервера.
