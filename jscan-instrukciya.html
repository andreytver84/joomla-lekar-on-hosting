Как пользоваться сканером jscan.php

Один PHP-файл для хостинга Joomla 5 и 6. Он сам удаляет только очевидные бэкдоры. Ядро сайта, шаблоны и .htaccess вслепую не трогает — спорное пишет в рапорт.

Этот HTML — только инструкция. На хостинг заливайте jscan.php, а не эту страницу. После работы удалите сканер с сервера.

Что подготовить

  • Файл jscan.php (лежит рядом с этой инструкцией).
  • Доступ в файловый менеджер / FTP Timeweb, чтобы залить файл в корень сайта.
  • Придумайте секретный ключ. Это не пароль админки Joomla, а пароль только для сканера. Пример: compas69-scan-7kR9pQ

Пошагово

  1. Смените ключ в файле (обязательно, до заливки)

    Откройте jscan.php в блокноте или в Cursor. Найдите примерно 10-ю строку:

    const JSCAN_KEY = 'change-this-key';

    Замените change-this-key на свой ключ. Кавычки не трогайте:

    const JSCAN_KEY = 'scan-7kR9pQ';

    Сохраните файл. Ключ из файла и ключ в адресной строке браузера должны быть одинаковые.

  2. Залейте файл на сайт

    Положите jscan.php в корень Joomla — туда же, где уже лежат configuration.php и index.php.

    Для Compas69 это обычно:

    /home/c/cr00000/Site/public_html/jscan.php

    Если чистите второй сайт Compas — тот же файл во второй public_html.

  3. Откройте сканер в браузере

    Подставьте свой ключ вместо примера:

    https://yoursite.ru/jscan.php?key=scan-7kR9pQ

    Если ключ неверный или его нет — будет страница Forbidden. Тогда проверьте: ключ в строке 10 файла и ключ после ?key= совпадают, файл точно залит в корень, не в подпапку.

  4. Нажмите «Полный цикл»

    Страница сама переходит по шагам (раз в секунду). Не закрывайте вкладку, пока не появится рапорт.

    ШагЧто происходит
    1Смотрит процессы и loadavg. Пытается убить только вредоносы вроде cli/cf. PHP и Apache не трогает.
    2Рекурсивно сканирует файлы (чанками, чтобы не упереться в таймаут хостинга).
    3Карантин и удаление очевидных бэкдоров, права 0755/0644, .user.ini без prepend.
    4Рапорт HTML + JSON.

    На shared-хостинге шаг 2 может идти несколько минут. Это нормально.

  5. Сохраните рапорт

    Нажмите «Скачать JSON». Файл также пишется на сервер:

    • tmp/jscan-report.json — для локального ИИ
    • tmp/jscan-report.html — для чтения глазами

    Если в JSON есть блок needs_ai_fix — откройте чат локально с копией сайта и этим JSON. Править нужно только перечисленные пути.

  6. Удалите сканер с хостинга

    Кнопка «Удалить jscan.php» в конце рапорта или руками через FTP. Не оставляйте файл на сайте.

Что сканер удаляет сам

Только высокая уверенность, и только после копии в tmp/jscan-quarantine/:
  • аплоадеры up_1234.pht / .shtml и файлы с текстом UPLOADER_OK, Gagal rename;
  • файлы с именем ровно cf или rt в папках cli/ и layouts/;
  • php/pht/shtml в images/, tmp/, cache/ (не ядро Joomla);
  • чужой auto_prepend_file в .user.ini.
Если копию в карантин записать не удалось — файл не удаляется, только попадает в рапорт.

Что сканер не трогает

Корневой .htaccess, configuration.php, index.php ядра, шаблоны и компоненты с подозрением на вставку. Их правит человек или локальный ИИ по списку needs_ai_fix.

Если процессы не убились

На Timeweb часто бывает Permission denied (errno 13). Это нормально: PHP не имеет права слать kill. В рапорте будет готовый текст тикета — скопируйте его в поддержку хостинга со списком PID.

Cron в панели Timeweb PHP не видит. Задания проверьте руками в панели.

Не делайте так:
  • не заливайте сканер, не сменив ключ;
  • не оставляйте jscan.php после работы;
  • не выкладывайте ссылку с ключом в открытый чат;
  • не заливайте на сайт эту HTML-инструкцию — она не нужна серверу.

Короткий чеклист

  1. Ключ в строке 10 jscan.php заменён.
  2. Файл лежит рядом с configuration.php.
  3. В браузере: /jscan.php?key=ВАШ_КЛЮЧ.
  4. «Полный цикл» → дождаться рапорта.
  5. Скачать JSON.
  6. Удалить jscan.php с сервера.
Файл сканера: jscan.php. Эту страницу можно открыть двойным щелчком на компьютере, на сайт её класть не нужно.
